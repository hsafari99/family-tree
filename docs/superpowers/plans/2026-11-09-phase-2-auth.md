# Phase 2 — Authentication: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** people can sign up, sign in and sign out with email and password. They can turn on authenticator-app 2FA with recovery codes, change their password, and reset a forgotten password either with an authenticator or recovery code, or with a one-time reset link. All of this is rate-limited and protected against CSRF, with no email ever sent.

**Architecture:**
- **Better Auth 1.7.18** is mounted at `/api/auth/*` in Fastify through a small adapter. It handles sign-up, sign-in, sessions, 2FA, recovery codes and password change.
- **Our own routes** under `/api/v1` add `GET /me` and the two password-reset flows that Better Auth doesn't offer:
  - **reset with an authenticator or recovery code**, which verifies against Better Auth's stored, encrypted 2FA records;
  - **one-time reset links**, stored hashed in our own table.
- **Shared Zod schemas** keep validation identical in the browser and on the server.
- **The web app** gains routing (react-router 8) and auth pages. Pages talk to an injectable `AuthApi` interface, so tests don't need a server.

**Tech stack (new):**
- better-auth 1.7.18: core, the drizzle adapter at `better-auth/adapters/drizzle`, the `twoFactor` plugin, `better-auth/crypto`, `better-auth/node`
- @better-auth/utils 0.5.1 (`createOTP`) and @node-rs/argon2 2.2.2
- @fastify/rate-limit 11.2.2
- react-router 8.5.1, qrcode 1.5.4 and @types/qrcode 1.5.6

All of these are older than pnpm's release-age window. Argon2 was verified on the dev CPU (no AVX2) both on the host and in Docker.

**Spec:** `docs/superpowers/specs/2026-11-09-family-tree-design.md` §5, §7 and §8. This plan covers phase 2 of §11.

**Verified facts about Better Auth 1.7.18** (from a scratch spike on 2026-11-09):
- **Tables and fields:**
  - `user` has name, email, emailVerified, image, createdAt, updatedAt and twoFactorEnabled.
  - `session` has expiresAt, token, createdAt, updatedAt, ipAddress, userAgent and userId.
  - `account` has accountId, providerId, userId, accessToken, refreshToken, idToken, accessTokenExpiresAt, refreshTokenExpiresAt, scope, password, createdAt and updatedAt.
  - `verification` has identifier, value, expiresAt, createdAt and updatedAt.
  - `twoFactor` has secret, backupCodes, userId, verified, failedVerificationCount and lockedUntil.
  - Every table also has `id`, and `generateId: 'uuid'` makes those ids UUIDs.
- **Enabling 2FA:** `auth.api.enableTwoFactor({ body: { password }, headers })` returns `{ method, totpURI, backupCodes }`, with 10 backup codes by default (we configure 8) such as `sCJis-ruroZ`. 2FA only becomes active after `verifyTOTP`.
- **TOTP secret:** the `secret` query parameter of `totpURI` is base32. The raw secret is `new TextDecoder().decode(base32.decode(secret))` (from `@better-auth/utils/base32`), and `createOTP(raw).totp()` produces a valid code.
- **Sign-in with 2FA on:** `signInEmail` returns `{ twoFactorRedirect: true, twoFactorMethods: ['totp'] }` and sets **3 cookies**: session_token, session_data and two_factor. The Fastify adapter must forward every `Set-Cookie` header, not just one.
- **Internals our reset routes need:** `(await auth.$context)` exposes `secret`, `password.hash()` and `internalAdapter.updatePassword(userId, hash)`. The 2FA secret and backup codes are stored with `symmetricEncrypt({ key: ctx.secret, data })`.
- **Telemetry** defaults to off. We also set `telemetry: { enabled: false }` explicitly.

**Decisions made in this plan** (the author can override any of them):
- Passwords must be 10–128 characters, with no character-type rules.
- Sessions last 30 days and refresh daily.
- The cookie prefix is `ft`.
- 2FA is optional for everyone in this phase. Requiring it for owners and stewards arrives with roles in phase 3.
- Reset links come with a dev-only CLI for testing. The owner UI for issuing them comes in phase 3.
- Google sign-in is deferred until the author creates an OAuth client.
- Account deletion is deferred to phase 3, because its rule depends on tree ownership.

**Carry-forward notes from phase 1 that this phase applies:**
- `AppError` replaces the generic 4xx-to-`BAD_REQUEST` mapping (Task 1).
- `/api/v1/health` gets rate-limited (Task 1).
- `trustProxy` becomes a config value (Task 2).
- Log redaction is revisited for session cookies (Task 6).

```ts
import type { ApiError } from '@family-tree/shared';
import { z } from 'zod';

type ErrorCode = ApiError['error']['code'];

/** The only error type whose message is shown to clients. */
export class AppError extends Error {
  override name = 'AppError';
  constructor(
    readonly code: ErrorCode,
    readonly statusCode: number,
    message: string,
    readonly details?: unknown,
  ) {
    super(message);
  }
}

export function parseBody<T extends z.ZodType>(schema: T, body: unknown): z.infer<T> {
  const result = schema.safeParse(body);
  if (!result.success) {
    throw new AppError('VALIDATION', 400, 'Some fields are invalid', z.flattenError(result.error).fieldErrors);
  }
  return result.data;
}
```

Rate-limit errors carry `statusCode: 429`, so map them to `RATE_LIMITED` with the message `Too many requests, try again later`. Use `errorResponseBuilder` to throw an `AppError('RATE_LIMITED', 429, …)`.

    2. `err.validation` → `VALIDATION`.
    3. 404 → `NOT_FOUND`.
    4. Any other 4xx → `BAD_REQUEST` with the message `Request could not be processed`, which never leaks `err.message`.
    5. Everything else → 500 `INTERNAL`.

```ts
import { z } from 'zod';

export const PASSWORD_MIN = 10;
export const PASSWORD_MAX = 128;

export const emailSchema = z.string().trim().toLowerCase().pipe(z.email('Enter a valid email address'));
export const passwordSchema = z
  .string()
  .min(PASSWORD_MIN, `Use at least ${PASSWORD_MIN} characters`)
  .max(PASSWORD_MAX, `Use at most ${PASSWORD_MAX} characters`);
export const nameSchema = z.string().trim().min(1, 'Enter your name').max(100);
export const totpCodeSchema = z.string().trim().regex(/^\d{6}$/, 'Enter the 6-digit code');

export const resetCodeSchema = z.union([totpCodeSchema, recoveryCodeSchema], { error: 'Enter a 6-digit code or a recovery code' });

export const signUpSchema = z.object({ name: nameSchema, email: emailSchema, password: passwordSchema });
export const signInSchema = z.object({ email: emailSchema, password: z.string().min(1, 'Enter your password') });
export const resetWithCodeSchema = z.object({ email: emailSchema, code: resetCodeSchema, newPassword: passwordSchema });
export const resetWithLinkSchema = z.object({ token: z.string().min(20).max(200), newPassword: passwordSchema });
export const meResponseSchema = z.object({

});
export type MeResponse = z.infer<typeof meResponseSchema>;
```

```ts
// OWASP 2024 minimum for argon2id: m=19 MiB, t=2, p=1 (~60 ms on the dev CPU).
const OPTIONS = { memoryCost: 19456, timeCost: 2, parallelism: 1 } as const;

export function hashPassword(password: string): Promise<string> {
  return hash(password, OPTIONS);
}

export async function verifyPassword({ hash: stored, password }: { hash: string; password: string }): Promise<boolean> {
  try {
    return await verify(stored, password);
  } catch {
    return false;
  }
}
```

```ts
import type { Config } from '../config.js';
import type { Db } from '../db/client.js';
import { accounts, sessions, twoFactors, users, verifications } from '../db/schema.js';
import { CLIENT_IP_HEADER } from './fastify-adapter.js';
import { hashPassword, verifyPassword } from './password.js';

export interface AuthOptions {
  config: Config;
  db: Db;
  /** Tests can turn Better Auth's own rate limiter off or tighten it. */
  rateLimitEnabled?: boolean;
}

export function createAuth({ config, db, rateLimitEnabled = true }: AuthOptions) {
  return betterAuth({
    appName: 'Family Tree',
    baseURL: config.AUTH_BASE_URL,
    basePath: '/api/auth',
    secret: config.SESSION_SECRET,
    trustedOrigins: [config.WEB_ORIGIN],
    telemetry: { enabled: false },
    database: drizzleAdapter(db, {
      provider: 'pg',
      schema: { user: users, session: sessions, account: accounts, verification: verifications, twoFactor: twoFactors },
    }),
    emailAndPassword: {
      enabled: true,
      minPasswordLength: PASSWORD_MIN,
      maxPasswordLength: PASSWORD_MAX,
      autoSignIn: true,
      requireEmailVerification: false,
      revokeSessionsOnPasswordReset: true,
      password: { hash: hashPassword, verify: verifyPassword },
    },
    emailVerification: { sendOnSignUp: false },
    session: { expiresIn: 60 * 60 * 24 * 30, updateAge: 60 * 60 * 24 },
    rateLimit: {
      enabled: rateLimitEnabled,
      storage: 'memory',
      window: 60,
      max: 100,
      customRules: {
        '/sign-in/email': { window: 60, max: 5 },
        '/sign-up/email': { window: 60 * 60, max: 10 },
        '/two-factor/*': { window: 60, max: 5 },
        '/change-password': { window: 60 * 15, max: 5 },
      },
    },
    advanced: {
      cookiePrefix: 'ft',
      useSecureCookies: config.NODE_ENV === 'production',
      database: { generateId: 'uuid' },
      // The adapter puts Fastify's request.ip (proxy-aware only when TRUST_PROXY) in this header,

    // Spec §5: 8 one-time recovery codes. Better Auth stores them encrypted (the spec said hashed; encrypted is accepted).
    plugins: [twoFactor({ issuer: 'Family Tree', backupCodeOptions: { amount: 8 } })],
  });
}

export type Auth = ReturnType<typeof createAuth>;
```

- [ ] **Step 3: Implement the adapter** in `auth/fastify-adapter.ts`:

```ts
import type { FastifyPluginAsync } from 'fastify';
import { fromNodeHeaders } from 'better-auth/node';
import type { Auth } from './auth.js';

export const CLIENT_IP_HEADER = 'x-ft-client-ip';

export const authRoutes: FastifyPluginAsync<{ auth: Auth }> = async (app, { auth }) => {
  app.route({
    method: ['GET', 'POST'],
    url: '/api/auth/*',
    async handler(request, reply) {
      const headers = fromNodeHeaders(request.headers);
      headers.set(CLIENT_IP_HEADER, request.ip); // overwrite anything the client sent
      const response = await auth.handler(
        new Request(new URL(request.url, auth.options.baseURL), {
          method: request.method,
          headers,
          body: request.body === undefined ? undefined : JSON.stringify(request.body),
        }),
      );
      reply.status(response.status);
      response.headers.forEach((value, key) => {
        if (key !== 'set-cookie') reply.header(key, value);
      });
      const cookies = response.headers.getSetCookie();
      if (cookies.length > 0) reply.header('set-cookie', cookies);
      return reply.send(response.body ? Buffer.from(await response.arrayBuffer()) : null);
    },
  });
};
```

```ts
// Re-check both files whenever better-auth is upgraded; password-reset.int.test.ts will fail if they drift.
import { createOTP } from '@better-auth/utils/otp';
import { symmetricDecrypt, symmetricEncrypt } from 'better-auth/crypto';
import { and, eq } from 'drizzle-orm';
import type { Db } from '../db/client.js';
import { twoFactors } from '../db/schema.js';

export async function verifyAndConsumeSecondFactor(
  db: Db,
  secretKey: string,
  userId: string,
  code: string,
): Promise<boolean> {
  const [row] = await db
    .select()
    .from(twoFactors)
    .where(and(eq(twoFactors.userId, userId), eq(twoFactors.verified, true)));
  if (!row) return false;

  if (/^\d{6}$/.test(code)) {
    const secret = await symmetricDecrypt({ key: secretKey, data: row.secret });
    return createOTP(secret, { digits: 6, period: 30 }).verify(code, { window: 1 }); // match better-auth's options
  }

  // Backup codes: do this read-modify-write inside db.transaction with SELECT ... FOR UPDATE on the two_factors row,
  // so two concurrent requests can't both spend the same code. Also return false while row.lockedUntil > now().
  const codes = /* decrypt + parse exactly as better-auth stores them */ await readBackupCodes(secretKey, row.backupCodes);
  const index = codes.indexOf(code);
  if (index === -1) return false;
  codes.splice(index, 1);
  await db
    .update(twoFactors)
    .set({ backupCodes: await writeBackupCodes(secretKey, codes) })
    .where(eq(twoFactors.id, row.id));
  return true;
}
```

```ts
import { createHash, randomBytes } from 'node:crypto';
import { and, eq, gt, isNull, sql } from 'drizzle-orm';
import type { Db } from '../db/client.js';
import { resetLinks } from '../db/schema.js';

const hashToken = (token: string) => createHash('sha256').update(token).digest('hex');

export async function createResetLink(
  db: Db,
  { userId, createdByUserId, ttlHours = 24 }: { userId: string; createdByUserId: string | null; ttlHours?: number },
): Promise<{ token: string; expiresAt: Date }> {
  const token = randomBytes(32).toString('base64url');
  const expiresAt = new Date(Date.now() + ttlHours * 3_600_000);
  await db.insert(resetLinks).values({ tokenHash: hashToken(token), userId, createdByUserId, expiresAt });
  return { token, expiresAt };
}

/** Atomically marks the link used; returns the user id, or null if invalid, expired or already used. */
export async function consumeResetLink(db: Db, token: string): Promise<string | null> {
  const [row] = await db
    .update(resetLinks)
    .set({ usedAt: sql`now()` })
    .where(and(eq(resetLinks.tokenHash, hashToken(token)), isNull(resetLinks.usedAt), gt(resetLinks.expiresAt, sql`now()`)))
    .returning({ userId: resetLinks.userId });
  return row?.userId ?? null;
}
```
